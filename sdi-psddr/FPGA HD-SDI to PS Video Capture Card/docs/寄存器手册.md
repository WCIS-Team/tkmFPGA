# 寄存器手册 · SDI 数据搬运通路

> 顶层模块：`sdi_cap_top`
> 对应 RTL：`rtl/cap/sdi_cap_regs.v`
> 对应头文件：`ps/sdi_cap.h`

---

## 零、怎么访问

| 项 | 值 |
|---|---|
| 基址 | **`0x8000_0000`**（PS 侧 **GP1** AXI 窗口） |
| 窗口大小 | 64 KiB（地址截到低 12 bit，实际用到 `0x00`–`0x74`） |
| 数据位宽 | 寄存器 32 bit；**写帧器那条路是 64 bit** |
| 端序 | 小端 |
| 握手 | 标准 AXI4-Lite，1 拍读写 |

两条 AXI 通路的分工（2026-10-15 更正，之前写的是 GP0）：

| 通路 | 谁当主机 | 干什么 | 位宽 |
|---|---|---|---|
| `S_AXI_HP2` | **PL**（写帧器） | 把像素写进 PS DDR | 64 bit |
| `M_AXI_GP1` | **PS** | 读写本寄存器块 | 32 bit (AXI4-Lite) |
| `M_AXI_GP0` | — | **不用**（原来挂在这里，方向反了） | — |

PL 往 PS DDR 写数据**只能走 `S_AXI_HP*`**：`M_AXI_GP0/1` 是 PS 发起的出口，
PL 挂在上面只能当从设备。厂商自己的写帧器也是挂 HP2。
两个口各挂一个从设备，没有地址译码，理由见 `设计说明.md` §3.1 / §6.18。

### ★ 这个块不做格式判断 ★

寄存器里**没有**"目标幅面""目标帧率"这类会影响数据通路的配置。

- 想知道源是什么格式 → 读 `MEAS_*` / `FPS_X100` / `RX_*`
- 想控制 → 只写 `CTRL` / `BUF_ADDR` / `RING_BYTES` / `REARM`

写 `EXP_FPS` 不会让硬件只收 25 或只收 30，它只是给软件记一个"我期望"，
然后可以在 `FPS_MATCH` 里看到实测是否一致。

| `0x04` | `VERSION` | RO | `0x0001_0000` | 高 16 位=主版本，低 16 位=次版本 |
| `0x08` | `CTRL` | RW | 0 | 见下 |

| `0x34` | `FPS_MATCH` | RO | — | 实测 == 声明 ? |

| `0x3C` | `FRAME_BYTES` | RO | — | 建议帧字节数 = `MEAS_H × MEAS_W × 2` |
| `0x40` | `BUF_ADDR_L` | RW | 0 | 环形缓冲区物理地址低 32 位 |
| `0x44` | `BUF_ADDR_H` | RW | 0 | 高 32 位 |
| `0x48` | `REARM` | W | 0 | **写 1**：按当前 `BUF_ADDR` 重新开始写，清 `FRAME_CNT`/`BEATS` |
| `0x4C` | `FRAME_CNT` | RO | 0 | vsync 次数 |
| `0x50` | `FRAME_ADDR` | RO | 0 | 上一次 vsync 那一拍的**字节地址**低 32 位 |
| `0x54` | `WR_ADDR` | RO | 0 | 下一个拍将写到的字节地址低 32 位 |

| `0x6C` | `RING_BYTES` | RW | 0 | 环形缓冲长度。**0 = 不环绕**（用满 32 位空间） |
| `0x70` | `LINE_CNT` | RO | 0 | 行计数，自由运行 |
| `0x74` | `WR_IDLE` | RO | - | bit0 = 写帧器已排空。见下 |

## 一点五、`WR_IDLE`（`0x74`）：复位/重配置前的判空位

| 位 | 名称 | 说明 |
|---|---|---|
| 0 | `IDLE` | 1 = **HP2 上没有在途突发**，写帧器状态机已回空闲 |

**为什么需要它**：厂商《PS-PL AXI HP 接口：事务计数与复位语义》写明，
PS 侧不提供在途事务计数（没有 AFI，也没有 `RCOUNT`/`RACOUNT`），
AXI 协议本身也不定义这类信号。AXI 不要求"复位时把在途事务做完"——
一侧在非空闲时被复位，另一侧会一直等下去。凡是只动 PL 的操作
（PL 重配置、PL 逻辑复位）都必须先排空，而判空只能靠 PL 自己报。

硬件侧就是一个单 bit：`inflight == 0 && state == S_IDLE`，
产生在 **`clk_100m` 域**（AXI 主机所在域，不再随像素时钟换频），两级同步到 FCLK0。
`inflight` 在 `BRESP` 回来时才减，所以 `IDLE=1` 也意味着**最后一笔写响已经收到**。

> 只有 1 bit 可以这样做。多 bit（比如把 6 位在途计数整体跨过去）
> 会有撕裂/亚稳态，不能用来判空。

### ★ `IDLE=1` **不等于** "FIFO 空了"

写帧器只在水位 ≥ 16 拍（一个完整突发）时才起一笔，所以**源停下来时**，
FIFO 里会合法地剩下 **最多 15 个拍（120 字节）** 发不出去：

```
停源 -> 最后一笔发完（等 BRESP 回来）-> inflight=0 -> IDLE=1
                                       FIFO 里可能还剩 0..15 拍
```

软件看到 `IDLE=1` 时：
- **可以**复位/重配置 PL（在途事务已清零，`IDLE=1` 就是这件事的充分条件）；
- **不要**把"FIFO 空"当成判据（硬件根本没暴露 FIFO 水位）；
- 想确认"最后那点数据也没丢"：对比 `BEATS` 与源侧像素数，差 0..15 拍属于正常。

**软件用法**：关 `ENABLE` 之后轮询本寄存器，
要求连续 3 次 bit0 都是 1 才认为排空。`sdi_cap_stop()` 已经这么做了；
复位或重配置 PL 之前应当照做。

## 二、CTRL (`0x08`)

| 位 | 名称 | 说明 |
|---|---|---|
| 0 | `ENABLE` | 通路使能。0 = 停止写 PS DDR |
| 1 | `IRQ_EN` | 中断总使能 |

**只有一个使能，没有"目标幅面""目标帧率"。** 这是这个设计的核心。

> `ENABLE = 0` 时像素不再进 FIFO，`WR_ADDR` 停在原地；
> 重新置 1 会从当前地址继续（不会跳回 `BUF_ADDR`，要跳回去得写 `REARM`）。

---

## 三、STATUS (`0x0C`)

| 位 | 名称 | 说明 |
|---|---|---|
| 8 | `ENABLE` | 与 `CTRL.ENABLE` 同值，方便单读判断 |
| 9 | `BUSY` | 正在发突发 |
| 10 | `SIG_LOCKED` | SDI 传输格式已锁。**只上报，不参与数据门控** |
| 11 | `GEOM_VALID` | 幅面已经测出来了（`MEAS_W`/`MEAS_H` 非零） |
| 12 | `STARVING` | 长时间没有像素进来 |
| 13 | `ERR` | `ERR_STAT` 非零 |

### ★ 排障判据表（黑屏时按这个顺序读）★

| `SIG_LOCKED` | `BEATS` 变化 | `FRAME_CNT` 变化 | 含义 |
|---|---|---|---|
| 0 | 否 | 否 | **GT 没拿到参考时钟或没锁定** → 查跳线 J26/J27、SDI 电缆 |
| 0 | 是 | 是 | GT 出数据了但认不出格式 → 相机可能切到 CVBS 了（见 `上板检查.md`） |
| 1 | 否 | 否 | `ENABLE` 没置位，或 FIFO 一直空 |
| 1 | 是 | 否 | 有像素但没有 vsync → 格式残缺，或 vsync 极性不对 |
| 1 | 是 | 是 | **通了**，去读 `MEAS_*` 看幅面 |

## 四、帧率相关

### FPS_CLASS (`0x30`)

| 值 | 含义 |
|---|---|
| 0 | 未知（`FPS_X100` 不在任何一个容差窗里，或还没测出周期） |
| 1 | ~25 |
| 2 | ~30（含 29.97） |
| 3 | ~50 |
| 4 | ~60 |

判定是**测出来的，不是查表**：HD-SDI 像素时钟恒 74.25 MHz，1080p 垂直总行数
恒 1125，但总水平样点随帧率变（25 → 2640，30 → 2200）。所以
`fps = 74250000 / MEAS_FPER`，硬件里用一个 64 拍迭代除法器算。

容差 ±3%，所以 29.97 落在 30 那一档。

`SIG_LOCKED = 0` 时 `MEAS_FPER` **不更新**（周期没意义），
但 `LINE_CNT` / `FRAME_CNT` 照走——"计数在动但周期不动"本身就是
"GT 活着但认不出格式"的判据。

### EXP_FPS (`0x2C`)

| 值 | 含义 |
|---|---|
| 0 | 不指定（默认）。`FPS_MATCH` 恒为 1 |
| 1 | 期望 25 |
| 2 | 期望 30 |

**不影响数据通路。** 只在 `FPS_MATCH` 里做对比。

## 六、错误与中断

### ERR_STAT (`0x5C`)，**只读**（粘滞）；清零靠 `REARM`

| 位 | 名称 | 说明 |
|---|---|---|
| 0 | `FIFO_FULL` | FIFO 满，**整拍（8 字节 = 4 像素）被丢掉**。粘滞，**清零靠 `REARM`** |
| 1 | `AXI_RESP` | AXI 写响应不是 OKAY。粘滞，**清零靠 `REARM`** |

> **这两个位不是 RW1C。** 它们住在写帧器里（`clk_100m` 域），CSR 这侧只是
> 把值转出来给你看；**往 `ERR_STAT` 写 1 什么也不会发生**，清零的唯一办法是
> 写 `REARM`（`REARM` 本来就要在配置缓冲区之后做一次，顺带清掉）。
> 这条是 `tb_sdi_cap_regs` 验过的（判据 `ERR_STAT after write (unchanged)`）。
> 2026-10-15 之前手册写成 RW1C，实现里也从来没有把清零接到写帧器上 ——
> 文档和实现各说各的（见 `设计说明.md` §6.25 同一条教训）。
>
> 丢的粒度是**整拍**：FIFO 满时读指针不动、写指针跳过那一拍，
> 所以内存里不会出现"写了一半的拍"，但帧内会缺 4 个像素。
> 硬件**不会反压 SDI 接收器**（反压会让 GT 失锁）——宁可丢也不反压，
> 这是刻意的取舍。
>
> 正常负载下（1080p30 只要 124.4 MB/s，口子有 800 MB/s）它**不应该**置位。
> 置位说明 WREADY 长期不给：内存带宽被别的 master 抢了，或者软件把
> AXI 主机别在什么地方了。
>
> 这条通路在测试台上是验过的：`sim/run_bench.ps1` 的 `W_LAT_8` 套件把 WREADY
> 占空比压到 12.5%，丢 11226 拍，`ERR_STAT[0]` 必须置起来（判据 `ovf=PASS`）。
> 2026-10-15 之前测试台把 `px_overflow` 硬接 `1'b0`，**这条报错通路从来没被验证过** ——
> 而同期综合日志里它恰好是悬空的（见 `设计说明.md` §6.21）。
> 也就是说：这一个判据同时补上了"仿真没验"和"网表断了"两件事里的一半。

### INT_STATUS (`0x60`)，RW1C

| 位 | 名称 | 含义 |
|---|---|---|
| 0 | `FRAME` | 收到一次 vsync |
| 1 | `WR_ERR` | 写帧器出错 |
| 2 | `STARVING` | 长时间没有像素进来 |
| 3 | `NO_SIGNAL` | 没有 SDI 信号 |

`IRQ` = `IRQ_EN & (|(INT_STATUS & INT_ENABLE))`，接到 `pl_ps_irq0[0]`。

## 七、典型流程

```c
/* 1. 确认位流在（读魔数） */
if (rd(ID) != 0x53444943) { 位流没加载，或者这不是采集通路 }

/* 2. 先停 */
wr(CTRL, 0);
wr(INT_STATUS, 0xFFFFFFFF);      /* INT_STATUS 是 W1C */
/* ERR_STAT 是只读的，写它没用 —— 下面 REARM 那一步才会清掉它 */

/* 3. 配缓冲区 —— 注意：没有幅面参数，没有帧率参数 */
wr(BUF_ADDR_L, (uint32_t)ring_pa);
wr(BUF_ADDR_H, (uint32_t)(ring_pa >> 32));
wr(RING_BYTES, ring_len);        /* 0 = 不环绕 */
wr(REARM, 1);                    /* 装载起始地址、清计数器与 ERR_STAT */

/* 4. 开 */
wr(CTRL, CTRL_ENABLE | CTRL_IRQ_EN);

/* 5. 等一会儿，读实测值 —— 格式判断在这里，不在硬件 */
sleep(1);
rd(MEAS_W); rd(MEAS_H); rd(FPS_X100); rd(RX_FAMILY); rd(STATUS);

/* 6. 取帧：FRAME_ADDR 是 vsync 时的写地址 */
addr = rd(FRAME_ADDR);
w = rd(MEAS_W);  h = rd(MEAS_H);
row = rd(ROW_BYTES);            /* = w*2 */
grab(addr, row, h);             /* 逐行处理跨环尾，见 ps/sdi_cap.c */

/* 7. 停 */
wr(CTRL, 0);
```

**没有 `CROP_W`/`CROP_H`，没有 `SEL_FPS` 门控。** 幅面来自实测，
帧率只上报不拦截。

## 八、帧边界

PL **不切帧**。只在 vsync 到达的那一刻记下当时的写地址（`FRAME_ADDR`）。

**帧标记是跟着数据一起过 FIFO 的**：打包器在 vsync 那一拍上打一个标记位
（`{marker, 4×16 像素}`，位 64），写帧器在把这一拍发上 AXI 总线时记下它的字节地址。
所以 `FRAME_ADDR` 就是**那一拍的地址**，不是"某个稍后到达的跨域脉冲"：

- 优点：`FRAME_ADDR` 与内存里的数据**严格对齐**，真实帧首误差 ≤ 1 拍 = **8 字节**；
- 对比：如果用"vsync 脉冲 → 两级同步 → 读当前写地址"，最坏会偏好几拍
  （同步延迟 + 突发在途），而且那个偏差**随突发长度变化**，软件没法修。

软件轮询它：值变了就是一帧开始。帧首在那个 8 字节窗口里的哪 4 个像素，
按已知的帧起始相位判断（1080p 帧首就是行首像素）。

帧长自己算：

```
ROW_BYTES   = MEAS_W  × 2
FRAME_BYTES = MEAS_H × MEAS_W × 2
```

帧与帧之间在内存里是连续的，中间没有空洞——写帧器从不停止。
读的时候要**处理环形回绕**（行可能跨环尾），`sdi_cap_grab()` 已经按行处理了。

如果软件读得比 PL 写得慢，旧帧会被覆盖，`ERR_STAT.FIFO_FULL` 会置位。

## 九、字节序

小端。64 bit 拍 n 里：

```
[15:0]   像素 4n+0
[31:16]  像素 4n+1
[47:32]  像素 4n+2
[63:48]  像素 4n+3
```

所以环形缓冲**逐字节等于 SDI 口收到的内容**：Y'CbCr 4:2:2 8 bit / 分量。
像素偶数列 `[15:8]=Y'`、`[7:0]=Cb 或 Cr`；奇数列 `[15:8]=Y'`、`[7:0]=另一个色度`。

没有做色彩空间转换、没有缩放、没有滤波。
